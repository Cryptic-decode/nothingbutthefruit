## Implementation workflow

- Understand the business goal and inspect the existing implementation before changing code.
- Preserve working functionality, established flows, and brand identity.
- Clearly identify what is good enough, weak, missing, or uncertain.
- Resolve important scope questions before implementation.
- Separate the minimum viable version from future improvements.
- Break substantial work into clear phases with deliverables and acceptance criteria.
- Complete and validate one phase before moving to the next.
- Do not silently expand the agreed scope.
- Prefer simple, reusable solutions that follow existing project patterns.
- Run appropriate lint, type, build, and functional checks after changes.
- Summarize what changed, what was preserved, and any remaining risks.
- Provide a concise commit message for commit-worthy changes.
